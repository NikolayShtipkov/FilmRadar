# FilmRadar: сценарий за защита

## Подготовка

Стартирайте `dotnet run --project src/FilmRadar.Web --launch-profile demo`. Използва се отделна база с шест измислени записа. Добавете собствен TMDB Read Access Token чрез User Secrets за live частта. Проверете търсене на `Interstellar`, подробности и препоръки преди представянето. Не показвайте токена на екрана.

Отворете `output/pdf/FilmRadar-Presentation.pdf` и приложението. Подгответе локалния списък като offline резервен вариант. Live демонстрацията още трябва да бъде репетирана със собствения ви token.

## Демонстрация: около 7 минути

| Време | Действие | Какво доказва |
|---|---|---|
| 0:00–0:45 | Представяне на проблема, MVC и технологиите | Цел и архитектура |
| 0:45–1:30 | Профил: любими жанрове, период и минимум | Форми, валидация, persistence |
| 1:30–2:30 | Търсене по заглавие, отделно Discover филтри, детайли | Външно API, async/await, HttpClient |
| 2:30–3:40 | Добавяне, повторно добавяне, гледан, оценка 0, любим, бележка | Unique защита, nullable enum, SQLite |
| 3:40–4:30 | Връщане към „За гледане“ с потвърждение, после отново гледан | Domain инварианти и validation |
| 4:30–5:40 | Настроение и препоръки, причини, изключване на гледан филм | Mock AI, bounded workflow, scoring |
| 5:40–6:20 | Изключване на интернет след зареждане, локален списък и редакция | Offline persistence и graceful errors |
| 6:20–7:00 | Тестове, ограничения, идеи за следваща версия | Качество и разбиране на решенията |

За премахване на запис отворете confirmation страницата и потвърдете изрично. Не изтривайте произволни лични данни по време на защита. Demo seed връща липсващите примерни записи при следващ demo старт.

## Въпроси за подготовка

- Защо `null` и `0` са различни и къде се валидират?
- Защо не филтрираме само първата Search страница локално?
- Какво става с DbContext при паралелни операции?
- Какво означава active-weight normalization?
- Защо 9/10 от 2 гласа има по-малък TMDB принос от 8/10 от 500 гласа?
- Защо „За гледане“ няма допълнителен бонус?
- Какво предпазва формите от CSRF и бележките от HTML injection?
- Защо приложението не е готово за публичен multi-user hosting?

## Браузърна проверка и screenshots

Python е нужен само за допълнителните QA скриптове, не за .NET приложението. На собствената си машина, от корена на solution:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install playwright
.venv\Scripts\python scripts/browser-smoke.py --channel msedge
```

Изисква инсталиран Edge и вече стартирано приложение. Алтернатива: `python -m playwright install chromium`, после `--channel chromium`. Скриптът не променя данните и създава desktop/mobile screenshots в `docs/screenshots/`. Прегледайте ги визуално, проверете клавиатурната навигация и запазете подходящите кадри за защитата. Снимайте live results и препоръките ръчно след настройка на TMDB token.

В ограничената агентска среда браузърният процес беше блокиран от Windows permissions. Скриптът е предоставен, но не е отчетен като успешно изпълнен там.

## Презентация

PDF слайдовете са в `output/pdf/FilmRadar-Presentation.pdf`. Източникът е `scripts/build-presentation.py`. За редакция на текста и повторно генериране използвайте `reportlab` и TrueType шрифт с кирилица:

```powershell
.venv\Scripts\python -m pip install reportlab
.venv\Scripts\python scripts/build-presentation.py
```

По подразбиране скриптът използва Windows Arial. На друга ОС посочете `--font` и `--bold-font` с подходящи локални TTF файлове. Преди защита добавете своето име, факултетен номер и курс към заглавния слайд.
